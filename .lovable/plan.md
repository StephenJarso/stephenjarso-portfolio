# Stephen Jarso portfolio

## Goal
Build a polished, responsive engineering portfolio that makes Stephen’s backend, Go, DevOps, and security focus immediately clear, while keeping every claim truthful.

## Pages and navigation
- Create a shared sticky navigation and footer across the site.
- Build dedicated pages for Home, About, Projects, Skills, Experience, Writing, and Contact.
- Add dedicated case-study pages for Secure Push, AgriChama, Social Network, and Guidely.
- Use working mobile navigation and clear links between project summaries and case studies.

## Visual direction
- Use an editorial warm off-white, charcoal, olive, and sepia design system.
- Pair Cormorant Garamond headings with Inter body text.
- Create restrained technical diagrams from styled interface elements rather than stock art.
- Add subtle reveal, connection-flow, cursor, button, and card motion with reduced-motion support.
- Design desktop, tablet, and mobile layouts intentionally rather than shrinking one layout.

## Content
- Build the supplied hero, engineering introduction, “What I build,” selected work, technical toolkit, journey, experience, open-source, writing, contact, and footer sections.
- Keep projects in reusable structured data so summaries and case studies stay consistent.
- Clearly label missing experience, repository, live-demo, article, resume, and social-link details as editable placeholders instead of inventing facts.
- Include architecture diagrams and all requested case-study sections without fabricated metrics.

## Quality and discoverability
- Use semantic structure, keyboard-accessible controls, strong focus states, sufficient contrast, and descriptive labels.
- Add unique titles, descriptions, social metadata, canonicals, structured data, and crawler files for public pages.
- Verify the finished site at desktop and mobile sizes, test navigation and menus, and resolve preview errors.

## Technical details
- Keep the existing TanStack Start and Tailwind setup while implementing the requested React/TypeScript component architecture.
- Use reusable components for navigation, diagrams, project cards, timelines, calls to action, and footer content.
- Use Lucide icons and semantic design tokens; no database or external service is required.
